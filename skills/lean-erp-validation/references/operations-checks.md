# 部署与 OTA 的专项验证

仅安装、配置、备份恢复或 OTA 本身变化时读取。它们不是每次 ERP 业务修改的前置验收。

- 按本次变更定位 scripts/tests/ 的相关用例、升级接口与页面。只改提示文案不跑镜像升级演练；改执行顺序、恢复、持久化或安装脚本才验证相应真实链路。
- 入口、配置和故障处理以仓库根目录 README.md、docs/LEAN_OTA_OPERATIONS.md 为准，不在技能复制部署协议、版本号或恢复步骤。使用独立 Compose 项目、新数据库及新卷，不操作已有实例；schema guard 拒绝不能靠清库或关闭保护解决。
- 声称网页升级可用须有真实执行器心跳；声称容器重建可恢复须实际重建核对版本和任务。涉及备份/迁移须证明完整备份先于迁移，迁移失败不启动旧程序；修改进程恢复时在改变的中断点注入故障，不能只用健康页代替恢复证据。
- 声称备份可恢复须在独立空库及附件目录实际恢复并核对数据；哈希、文件存在或 pg_restore --list 仅证明相应检查，不能冒充还原成功。不将容器内备份套用旧 ZIP 恢复脚本。
- 正式 Docker 包与原生包分别核对预构建镜像身份、离线 wheelhouse 等受影响交付物。现场构建或本地发布夹具通过不等于正式附件、远端下载或另一 CPU 架构通过。
- 预览可不启用 OTA；未验收能力明确标注。记录实际环境、范围和限制，不把测试环境完成说成用户 Linux 已升级，也不因 OTA 修改追加销售到收款全链。
