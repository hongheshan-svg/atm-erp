# 运维与企业试运行规程

所有命令必须显式指定目标配置。脚本不自动寻找生产凭据，不向外部发送消息。

## 本轮待企业补充

真实项目名称、参加人员、生产备份目录及告警接收方式由企业后续提供。以下为可执行规程，尚未实施生产调度或企业真实订单验收，不能据此标记上线验收通过。

## 备份调度接入

`scripts/backup_cycle.py` 复用一致性备份脚本，完成归档检查、异地挂载目录复制和 SHA256 复核，原子写入状态 JSON；任何一步失败退出1，不清理旧备份、不自动恢复。异地目录须由运维预先验证确在独立设备，脚本无法证明挂载背后设备的物理独立性。备份会短暂停止 app，请放在维护窗口。

```sh
python3 scripts/backup_cycle.py --env-file /明确路径/环境配置 --backup-dir /已建立的本地备份目录 --offsite-dir /已验证的异地挂载目录 --data-path /实际数据磁盘 --health-url http://明确目标/api/health/ --status-file /运维状态目录/backup-status.json
```

Linux 可由 systemd timer、macOS 可由 launchd、Windows 可由任务计划程序每天在维护窗口运行上述命令。设置禁止重叠执行、失败重试间隔和最长运行时间；监控必须同时采集退出码与状态文件更新时间，以发现任务根本没运行的情况。配置告警接收人后，人工制造一次失败并记录收到告警的证据。当前未给接收渠道，因此不宣称告警已送达。

## 日常检查

- 运维负责人每天检查备份任务退出码，成功归档存入独立目录并复制到另一台设备。仅文件存在不等于恢复可用。
- 使用 `python3 scripts/backup.py backup --env-file /明确路径/环境配置 --archive /备份目录/日期.zip`；失败退出码必须由现有主机调度/监控系统通知运维负责人，不能忽略失败继续记为成功。
- 使用 `python3 scripts/ops_check.py --backup-dir /备份目录 --data-path /实际数据磁盘 --health-url http://明确目标/api/health/`。默认检查最近26小时有非空备份、磁盘至少5GB余量和健康接口；返回JSON，异常退出1。阈值可按企业容量调整。
- 此检查不清理备份、不修改数据、不新增常驻服务。主机监控应采集退出码并配置负责人；企业通知渠道和排班由实际运维确认。

## 恢复演练与发布

1. 每月及关键版本发布前，对隔离的新项目、新卷运行恢复演练；禁止以生产库为恢复试验目标。
2. 记录备份时间、镜像版本、恢复耗时，比较业务行数和附件校验值，再用六角色验证权限及一笔完整业务链。
3. 发布前保存代码提交、镜像摘要、迁移版本、环境配置及一致的数据库/附件归档。生产必须使用 `LEAN_ENVIRONMENT=production`。
4. 发布后检查健康、登录限流、附件鉴权、业务页面及关键余额。旧镜像不能运行新数据库或绕过schema guard。
5. 如需回退，在独立环境恢复发布前数据库及附件，并使用匹配的旧镜像；验证后再切换入口，保留故障环境用于排查。切换前处理发布后新录入业务，不能直接丢弃。

## 脱敏真实订单试运行

由企业提供三个脱敏项目：同配置批量设备、不同配置分批交付、含设计变更和退换货的项目。不得把模拟数据测试标为企业试运行。

按管理员、经理、采购、仓库、财务、成员分别执行：建档签约→BOM→预算与剩余成本→采购付款期限→审批→多次到货及隔离处理→领退料→按批配套发货→安装验收→收付款与补凭证→合同减额退款→结项。

逐项记录：预计结果、实际结果、对应单号、执行角色、操作耗时、失败原因、复测结果。经理核对材料预测未重复包含在途；财务核对付款期限与合同条款；工程核对每批清单；仓库核对隔离和补货义务。业务负责人签认后才结束试运行。
