## 安全修复验证

受影响路径：匿名 HTTP 头 → Docker/native Nginx → LoginThrottle → 登录及刷新接口。原问题是整个任意 X-Forwarded-For 被当作限流身份。

安全不变量：限流身份必须来自可信连接边界，不能由未认证调用者选择；正常登录、刷新、不同真实客户各自配额和明确 development 模式保持可用。

采用共享 LoginThrottle 加两处入口覆盖的最小完整修复。没有关闭限流、降低认证强度或扩大可信代理范围。额外反向代理默认按其连接 IP 分组；不自动信任它携带的任意头。

按顺序验证：

1. 静态和构建：Ruff、Django check、makemigrations --check --dry-run、前端 ESLint/vue-tsc、Vite 与 Docker 构建通过。
2. 安全触发：实际 Nginx 前正常登录一次返回 200；再轮换 X-Forwarded-For、X-Real-IP、Forwarded，前 9 次失败认证返回 401，第 10/11 次返回 429（与正常登录合计超过 10 次）。携带多段伪造链的 refresh 也返回 429，原绕过不再复现。
3. 合法控制及回归：正常密码登录成功；单元测试验证两个真实代理客户独立计数、IPv6 规范化、无效头回退、直接请求不能伪造身份、refresh 与 login 共用限制、开发模式原有行为。独立只读审阅未发现支持的 Docker/native 路径存在残留绕过或回归。

核心安全文件：`backend/apps/accounts/api.py`、`backend/apps/accounts/tests/test_auth.py`、`docker/app/nginx.conf`、`scripts/native_install.py`、`scripts/tests/test_native_install.py`。
