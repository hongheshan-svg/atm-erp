# v1.8.42

本版整理管理员删除：以前被关联拦住后要一条条试、一个个列表去清，有些资料永远删不掉；现在一次说清哪些不能删、为什么，能一起处理的一起处理。删除仍然只整理列表，不撤销已发生的库存、资金和工时。没有数据库迁移。

## 本次更新

### 批量删除一次列出全部不能删除的记录
- 以前勾选多条记录时，系统遇到第一条不能删的就停下，只提示这一条，整批不动；去掉它再试，才知道下一条。
- 现在系统检查完整批，在确认框里列出全部不能删除的记录和各自的原因。点「去掉这 N 条，只删其余 M 条」后再确认，其余记录照常删除，删除原因不用重填。
- 只要还有一条不能删，整批仍然不会删除；系统不会自己跳过记录。

### 拦截原因写明是哪张单据
- 以前只说「此记录已被采购单使用」「项目已有项目任务」。现在写出具体单据，例如「往来单位仍有未结束的销售单（SO000006）」，最多列 3 个，并说明下一步怎么处理。

### 误建的单据不用先删附件
- 以前草稿销售单、草稿采购单、未使用的项目只要挂了附件就删不了，要先进附件弹窗逐个删。
- 现在未被引用的附件随单据一并删除，各自留有删除记录。附件已经作为收付款、对账单、补充协议或归档采购合同的依据时仍然拦住，并写明是哪个文件。

### 删除已取消或结项的项目，不用再到各列表删一遍
- 以前删除项目后，它的销售单、采购单、任务、工时、款项还留在各自的列表里，要逐个列表再删。
- 现在这些单据随项目一并移入「已删除记录」。仍在办的不会跟着隐藏，例如取消后待退款的款项及其收款流水：它们留在原列表，删除完成后会列出是哪几条、为什么，办结后可以单独删除。
- BOM、交付和附件只在项目页里出现，项目移出后不再出现在任何列表；从「已删除记录」打开原项目仍能看到。库存流水和银行流水是仓库和银行的总账，不随项目隐藏。

### 物料和往来单位：有历史单据的也能移出列表
- 以前物料只要进过 BOM、采购明细或建过库存行，往来单位只要被项目、销售单、采购单用过，就永远删不掉，停用后仍留在列表里。
- 现在分三种情况：
  - 从未被使用：直接删除（与以前相同）。
  - 只剩历史单据：停用并移出列表。编码和图号继续占用，历史单据照常显示该物料或往来单位。
  - 仍在办：拒绝并写明原因。物料是在未结束项目的 BOM 中、在未完成的采购单中，或还有库存；往来单位是有未结束的项目、销售单、采购单，或还有未结清、待退款的款项。
- 停用归档的物料和往来单位可以在「已删除记录」里点「恢复到列表」。恢复后仍是停用状态，核对后在编辑中启用。
- 「已删除记录」每条新增「处理方式」，写明是直接删除、只移出列表，还是停用归档，以及随哪个项目或单据一并处理。

## 升级说明

- 没有数据库迁移，没有配置变化。
- 导入 BOM 或新建物料时如果提示与某个已停用的物料重复，而在物料列表里找不到它，请到基础资料的「已删除记录」里恢复。
- 停用归档的物料和往来单位不能直接编辑，需先恢复。
- 接口：`record-deletions/` 被拦时新增 `blocked`（全部被拦记录的 id、label、reason），原 `blocked_id` 保留为其中第一条；成功结果的每条记录可带 `documents`、`cascaded`、`kept`、`kept_count`。`record-deletions/restore/` 的 `resource` 新增 `items`、`partners`。物料和往来单位的删除方式新增 `disable`。
- 拦截提示的文字有变化，按提示原文做判断的外部脚本需要更新。

## 验证

已完成：
- 改动前先在隔离库实测 30 多个删除场景，确认问题所在：批量只报第一条、草稿带附件被拦、项目归档后子单据仍在各列表、物料和往来单位有过引用就永远删不掉。
- 后端 business 717 项、concurrency 44 项通过（business 新增 8 项，覆盖一次列全被拦记录、附件随主单删除、凭证附件拦主单、项目连带子单据、在办子单据保留、物料与往来单位的停用归档和在办拦截、恢复与编辑保护）；checks 阶段（矩阵登记、Ruff、Django 检查、迁移检查）通过。
- 前端单元测试 726 项、ESLint、类型检查通过（删除确认框新增 6 项）。
- 在隔离预览环境用浏览器跑删除用例（桌面端）：新增两条通过，分别覆盖「列出被拦记录、去掉后删其余、停用归档后恢复」和「删除已取消项目连带销售单与款项」。
- 量过大项目的耗时：一个带 3700 条子单据（其中 3000 条工时）的已取消项目，删除用时约 5 秒。

未完成：
- 没有在有真实业务数据的正式服务器上验证；删除期间其他写入会排队等待，子单据特别多的项目建议在空闲时段删除。
- 「仍在办的记录留在结果页」这一步只有后端用例和前端单元测试覆盖，没有浏览器用例。
- 浏览器用例在同一预览库重复运行时，原有的「批量管理开关」用例因物料重名失败（首轮在干净库上通过），与本版改动无关；发版验证在干净环境重跑。

发布流程强制执行本版代码的发版验证，通过后才发布；不将其称为完整业务链验收。

## 📥 Installation

### Docker

下载下方对应平台的 `atm-erp-v1.8.42-<platform>-docker.zip`，解压并进入目录。仅需 Docker Engine / Docker Desktop（Linux 容器）与 Compose v2。包内 Compose 固定该版预构建多架构镜像摘要，不在本机构建。全新部署复制配置并填写随机密钥后启动：

```bash
# macOS / Linux
cp .env.example .env
chmod 600 .env
# 编辑 .env，填写数据库密码、SECRET_KEY 和管理员初始密码
docker compose up -d
```

```powershell
# Windows PowerShell
Copy-Item .env.example .env
# 编辑 .env 后
docker compose up -d
```

### Download (Linux · Docker)

在空目录下载并解压，再按上方步骤配置和启动；不要覆盖已有配置：

```bash
curl -fL https://github.com/hongheshan-svg/atm-erp/releases/download/v1.8.42/atm-erp-v1.8.42-linux-docker.zip -o atm-erp-v1.8.42-linux-docker.zip && unzip atm-erp-v1.8.42-linux-docker.zip
```

安装后默认访问 `http://127.0.0.1:8080/erp/`，用户名 `admin`，初始密码为 `.env` 的 `LEAN_ADMIN_PASSWORD`，首次向导要求修改。已有 `.env.lean` 的部署显式使用 `--env-file .env.lean`，不要新建配置替代。新版 Docker up 后默认接入容器内网页升级，无需宿主机执行器或 docker.sock；须保留 lean_runtime 卷。兼容范围、恢复及原生 Linux systemd 安装见 README。

### Manual download

从下方 **Assets** 下载适合平台的安装包：

- 平台：`macos` / `linux` / `windows`。
- 安装方式：`docker` / `native`；原生包包含预编译依赖，运行环境与安装步骤见 Installation Guide。
- SHA256 校验清单：`atm-erp-v1.8.42-SHA256SUMS.txt`。
