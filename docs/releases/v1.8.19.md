# v1.8.19

## 本次更新

本版是第二轮全面审计的整改，重点是资金和权限规则收紧、审批分离、BOM/采购/库存口径修正，以及流程进度和工作台的准确性；另外新增按错误编号查日志。

**资金与权限**

- 管理员删除不再允许删除仍在办理的记录：未结清的账款、草稿或仍有额度的对账、未匹配的银行流水、未验收或质保期内的交付，会提示先结清、作废或验收；已结束的记录仍可整理。
- 未参与项目的项目经理，看不到已签约销售单的合同额、回款、补充协议金额和合同附件，页面显示“无权查看”；未签约销售单不受影响。
- 同一笔到账不能先手工登记、再认领重复入账；一笔到账可以先认领一部分，剩余部分手工登记，登记金额以银行流水未匹配的余额为上限。
- 银行导入能识别已有的手工银行记录；疑似重复时整批不导入，提示补填流水号或作废误录记录。

**审批分离**

- 草稿阶段改过单价或数量的人，不能批准本单；待审期间调整预算、使本单不再超预算的人，不能普通批准本单。管理员仍可按原例外流程填写原因后批准。
- 工作台和流程进度的审批人与上述规则一致，不再显示本人提交、本人无法审批的单据。

**BOM、采购与库存**

- 同一物料用于多个单元时，收货后数量仍归属原 BOM 行，不会把缺口转到其他单元，也不能重复下单。
- BOM 修订和导入只校验本次改动的物料，提示中带物料编码和最低可改数量。
- 隔离品全部退回后，采购单恢复为待收货；合格入库日期不能早于到货日期。
- 采购退货要占用其他项目已到货的物料时，需要确认。
- 采购质保：报修数量扣除已退货数量；同一笔退货或费用不能关联多张质保单。

**流程进度与工作台**

- 已取消但仍需退款的款项显示“待退款”，由财务跟进；对账快照失效的草稿交给财务作废重建。
- 同名人员附带账号显示；收款节点显示签约时的节点名称；候选人员中，具体岗位排在管理员前面。
- 工作台不再显示已结项项目的销售单；待结算显示当前到期金额。
- 收付款页增加“待退客户款”“待收退款”；采购应付已付超过合格收货净额时，提示“已超付（预付）”。

**新增功能**

- 已签约销售单可转交负责人：只能由管理员或该项目负责人操作，不能转给操作人本人，原因记入审计。
- 首批发货后误建、尚未开工的阶段任务，可由项目经理填写原因后取消。
- 质保期内可登记收费售后，须填写非质保责任原因。
- 发货时可填写安装期限、验收期限，写入自动生成的任务。
- 物料导入时，同一行互相独立的字段错误一次报全。
- 误删的账号可在“已删除记录”中填写原因后恢复，恢复后保持停用，确认角色后再启用。
- “设置 → 历史数据核查”（仅管理员，可导出）列出 5 类历史问题：同一款项重复登记的银行收付款、认领与手工登记重复、疑似重复的银行记录、采购质保关联异常、已删除但仍在办的记录。清单只读，不自动修改数据。
- 服务器处理失败时提示错误编号；管理员可凭编号在 Nginx 访问日志和后端日志中找到同一请求、操作人和异常堆栈。

**稳定性与易用性**

- 修复两处数据库死锁：物料编辑与 BOM 物料导入之间、附件删除与采购/销售/签约之间。
- 损坏的 XLSX 导入返回中文提示，不再报服务器错误；导入时人员错误定位到对应列。
- 已删除的误建物料不再占用图号。
- 采购、任务列表标出逾期，状态显示完整；手机端详情面板占满视口，底部操作栏常驻。

## 兼容与验证

- 没有数据库迁移。新规则只约束今后的操作，不回溯修改历史数据；历史上已存在的问题请管理员在“历史数据核查”中查看，由财务或采购在原单上处理。
- 日志格式有变化：后端日志每行增加 `request_id=… user_id=…`，Nginx 访问日志行尾增加 `request_id=`。如有按旧格式解析日志的脚本，需要同步调整。原生安装要求 Nginx 1.11.0 及以上。
- 合并前，两项改动均已通过按影响范围选择的后端、前端、运维脚本测试与桌面/手机页面检查；请求编号改动另外通过了三平台安装器与 OTA 升级演练。
- 正式发布由 Release 强制执行发版验证：全部后端阶段、前端单测、运维脚本测试、按改动范围选取的双视口页面检查，以及本次 Nginx 与安装脚本改动触发的 OTA 升级演练和安装器检查。通过后构建并发布安装包。

## 📥 Installation

### Docker

下载下方对应平台的 `atm-erp-v1.8.19-<platform>-docker.zip`，解压并进入目录。仅需 Docker Engine / Docker Desktop（Linux 容器）与 Compose v2。包内 Compose 固定该版预构建多架构镜像摘要，不在本机构建。全新部署复制配置并填写随机密钥后启动：

```bash
# macOS / Linux
cp .env.example .env
chmod 600 .env
# 编辑 .env，填写数据库密码、SECRET_KEY 和管理员初始密码
docker compose up -d
```

```powershell
# Windows PowerShell
Copy-Item .env.example .env
# 编辑 .env 后
docker compose up -d
```

### Download (Linux · Docker)

在空目录下载并解压，再按上方步骤配置和启动；不要覆盖已有配置：

```bash
curl -fL https://github.com/hongheshan-svg/atm-erp/releases/download/v1.8.19/atm-erp-v1.8.19-linux-docker.zip -o atm-erp-v1.8.19-linux-docker.zip && unzip atm-erp-v1.8.19-linux-docker.zip
```

安装后默认访问 `http://127.0.0.1:8080/erp/`，用户名 `admin`，初始密码为 `.env` 的 `LEAN_ADMIN_PASSWORD`，首次向导要求修改。已有 `.env.lean` 的部署显式使用 `--env-file .env.lean`，不要新建配置替代。新版 Docker up 后默认接入容器内网页升级，无需宿主机执行器或 docker.sock；须保留 lean_runtime 卷。兼容范围、恢复及原生 Linux systemd 安装见 README。

### Manual download

从下方 **Assets** 下载适合平台的安装包：

- 平台：`macos` / `linux` / `windows`。
- 安装方式：`docker` / `native`；原生包包含预编译依赖，运行环境与安装步骤见 Installation Guide。
- SHA256 校验清单：`atm-erp-v1.8.19-SHA256SUMS.txt`。
