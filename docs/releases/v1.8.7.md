# v1.8.7 · 审计修复：锁账依据、共享库存冲突与列表规模

## 本次更新

### 业务规则

- **锁账不再卡住今天的纠错。** 此前判断一笔款项是否落在已锁期间，用的是这笔款项的**建单日**。取消采购未收余量、采购退货、取消费用和合同减额抵减都只是顺带更新旧款项的冲减金额，事情发生在今天，却因为原单开在上个月被「业务已锁账至 X」拒绝，而且无解——只能全期间解锁、操作、再锁一次。现按本次操作实际发生的日期判断；补录到锁定期间的收货日期仍然拒绝，锁账本身没有放松。
- **指派执行人的报错不再指错人。** 选了一个不在项目里的人员时，原来返回的是「无权访问此项目」，操作者会以为是自己权限不足。现在按字段返回「某某 不是该项目的负责人或成员，请先在项目中加入此人再指派」，派工、发货指定安装/验收人和代登记工时都适用；执行人下拉也同步只列项目成员、负责人和采购、仓管、财务这类跨项目岗位。
- **重开任务要确认执行人。** 已完成任务的执行人可能已被移出项目，此前重开必然失败且提示不明。现在重开时带执行人字段，原执行人已不在项目时不预选，直接改派。
- **共享库存的冲突摆到明面上。** 库存是全公司共享、不预留的，两个在执行项目各自查缺料时会把同一批库存都算成「可用」，于是两边都显示不缺料、都不下单。缺料表和采购选料区新增「其他项目待领」，列出其他在执行项目尚未领走的需求量和项目数；可用库存同时被别人盯着时标红。这是提示，不改变领料和采购的既有校验。
- **附件可以撤回。** 此前附件只能上传，传错文件、传错分类或传错项目只能再传一份，两份并存。现在上传者本人或项目经理可以删除，必须填写原因；记录、文件本体和上传审计都保留，已作为收付款、对账、补充协议或归档采购合同依据的附件一律拒绝删除。

### 性能与数据库

- **补上热点索引。** 采购审批要回查提交人、质保和处理记录要按单据回查，都落在审计日志这张增长最快的表上，此前没有任何索引，每次都是全表扫描。现补 `(resource, operation)` 索引，并把质保列表里逐条回查改为一次批量取回再分组。
- **物料查重不再整表扫描。** 建料、改料和 BOM 物料导入的每一行都要按规范化名称和图号查重，用的是函数表达式而没有对应索引；导入 1000 行就等于扫 1000 次物料表。现补名称与图号的函数索引，图号查重也改用与索引一致的表达式。
- **补齐复合索引。** 此前全库没有任何复合索引，只有外键和唯一约束自带的单列索引。现按实际过滤组合补上库存流水、应收应付、任务、工时和采购单的复合部分索引。
- **经营报表与关注视图不再全表遍历。** 「未来30天现金」和「账龄」此前把全库款项拉进内存，且每条还要额外两次聚合查询才能算出已收付金额。现在先在数据库层筛掉已结清的款项并一次注解净收付；经营报表同样只扫未结清款项，在途采购汇总也不再实例化全部采购明细。应收应付列表每行的账期拆分由算三四遍改为算一次。

### 界面与操作

- **下拉改为分页搜索。** BOM 维护、库存期初与领料、项目与任务、销售、附件上传、银行登记的物料、项目、客户和供应商下拉，此前会按每页 200 条把全量目录拉完再灌进选择框。非标设备行业每个机加件一个编码，物料上万时这意味着几十个请求和几万个选项节点，浏览器会卡住。现在统一走分页搜索，采购页早已采用的方式推广到全部模块。
- **任务有了全局清单。** 工作台「我的待办」此前点进去是项目列表，要看自己的活还得逐个项目点进去再切标签。项目页改为「项目列表 / 任务 / 工时记录」三个页签，任务支持按名称、项目和执行人搜索，默认只看分配给自己的，工作台分类入口直达。
- **维护 BOM 改为按需变更。** 此前打开就把整张 BOM 灌进逐行表单，每页 20 行，几百行的项目根本改不动，只能靠 Excel 导入绕过。现在空表起步，只填要新增或修改的物料；改单条用量可在「BOM 明细」里用「修改此行」，只提交这一行。服务端本来就只更新提交到的行，行为没有变化。
- **金额显示统一。** 千分位格式化此前在六个文件里各写一遍，工作台那份还换了实现，输出 `¥1,234.00`（没有空格且经过浮点转换），其余页面是 `¥ 1,234.00`。现收敛到一处，全站一致且不再经过浮点。
- **品牌与库位筛选改为关键词匹配。** 此前是精确匹配，输「施耐德」而库里存的是「Schneider」就只会得到空列表，提示也没说必须输完整值。
- **行操作菜单新增「更正与撤销」组。** 取消、作废、撤销、删除、冲销和退回修改不再和「下一步做什么」混排在同一组里。
- 预算面板头部回到与全站一致的两段式布局。

### 加固

- 改密接口新增每分钟 10 次限流。此前已登录会话可以无限次猜测原密码。
- 公司资料尚未初始化时执行锁账，返回「请先在设置中完成公司资料」而不是一个 404。

## 升级说明

沿用 Lean ERP 独立数据库。本版新增两个迁移，只创建索引，不改动任何表结构和数据；接口字段为新增，权限边界未变化。升级服务先备份后迁移。索引创建会短暂持有表锁，数据量大时建议在非业务时段升级。

升级后请留意：缺料表和采购选料区新增「其他项目待领」列；项目页由单一列表变为三个页签，默认仍停在项目列表；「维护 BOM」不再预先列出现有 BOM 行，改为只填本次变更。

## 📥 Installation

### Docker

下载下方对应平台的 `atm-erp-v1.8.7-<platform>-docker.zip`，解压并进入目录。包内包含 GitHub 预构建的 amd64/arm64 镜像，校验后直接安装，不在本机构建。需先安装 Docker Engine / Docker Desktop（Linux 容器）、Compose v2 和宿主机 Python 3.11。

```bash
# macOS / Linux
bash install.sh
```

```powershell
# Windows PowerShell
.\install.ps1
```

### One-line install (Linux · Docker)

在空目录执行，需已安装 Docker、Compose v2、Python 3.11、curl 和 unzip：

```bash
curl -fL https://github.com/hongheshan-svg/atm-erp/releases/download/v1.8.7/atm-erp-v1.8.7-linux-docker.zip -o atm-erp-v1.8.7-linux-docker.zip && unzip atm-erp-v1.8.7-linux-docker.zip && (cd atm-erp-v1.8.7-linux-docker && bash install.sh)
```

安装后默认访问 `http://127.0.0.1:8080/erp/`，用户名 `admin`，全新安装的初始密码见安装目录 `.env.lean` 中的 `LEAN_ADMIN_PASSWORD`。首次登录的安装向导会要求修改该密码，之后请使用向导中设置的新密码；忘记时按安装器结尾打印的命令重设。

### Manual download

从下方 **Assets** 下载适合平台的安装包：

- 平台：`macos` / `linux` / `windows`。
- 安装方式：`docker` / `native`；原生包包含预编译依赖，运行环境与安装步骤见 Installation Guide。
- SHA256 校验清单：`atm-erp-v1.8.7-SHA256SUMS.txt`。
