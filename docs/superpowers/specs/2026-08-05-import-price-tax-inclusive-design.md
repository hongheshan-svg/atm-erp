# 导入价格统一按含税口径解读

- 日期：2026-08-05
- 状态：已确认，待实现
- 相关：上一轮已上线的「采购申请含税单价录入」（commit 88c8753）

## 背景

用户反馈：拿到的供应商报价一律是含税价，但系统各处导入模板里的裸「单价」列按未税解读，导入后系统再叠一次税，含税总额虚高。这与手工录入时 319.20 被算成 360.70 是同一个坑的批量版本。

排查发现三个导入入口口径各不相同：

| 入口 | 代码位置 | 现状 |
|---|---|---|
| 采购申请导入 | `apps/purchase/views.py:409` | 有「未税单价」「含税单价」两列；**裸「单价」列按未税解读** |
| BOM 询价导入 | `apps/projects/views.py:1724` | 两列都认，至少填一项；只给含税时会反算未税；无裸列支持 |
| 物料主数据导入 | `apps/masterdata/views.py:118` | 「采购单价/销售单价/标准成本」三列，**完全无税率概念** |

## 决策：录入含税，入账未税

用户最初提出「全链路改为含税记账」。量化影响面后改为本方案：

- `unit_price` 被 **191 处**消费，横跨销售、采购、财务对账、库存 MRP、成本分析、询价比价 7 个模块；`estimated_price` 34 处
- 下游建立在未税基准上：`total_amount`（未税合计）→ 预算校验；`total_with_tax` → 应付账款 `amount_due`；`tax_amount` → 税务申报进项抵扣（`payable_amount = tax_amount - deductible_amount`）；收货 → 库存加权平均成本
- 翻转语义会让进项税额计算失去未税基数，且库存成本含进项税与「进项税可抵扣、不进成本」的会计准则冲突

**因此：用户看到和填写的一律是含税价，数据库入账的仍是未税价。** 使用体验就是「一切都是含税」，会计基准不动。

## 解析规则

三个入口统一：

1. 有明确的「未税单价」列 → 按未税读（用户显式声明了口径，尊重它）
2. 有「含税单价」列 → 按含税读，反算未税
3. **只有裸「单价」列 → 按含税读**（本次核心改动，从按未税翻转）
4. 两列都给 → 各按各的，不猜

税率优先级：**行内税率列 > 表头/单据税率 > 物料自身 `tax_rate` > 默认 13%**

反算公式沿用已上线的实现（`apps/purchase/models.py`）：

```
未税 = round(含税 / (1 + 税率/100), 2)   # ROUND_HALF_UP
含税 = round(未税 × (1 + 税率/100), 2)
```

### 各入口落点

| 入口 | 反算后写入 | 税率来源链 |
|---|---|---|
| 采购申请导入 | `estimated_price`(未税，入账基准) + `price_with_tax`(展示) | 行税率列 → 申请单表头 `tax_rate` → 13 |
| BOM 询价导入 | `price_without_tax` + `price_with_tax` + `tax_rate` | 行税率列 → 物料 `tax_rate` → 13 |
| 物料主数据导入 | `purchase_price` / `sale_price` / `standard_cost`（均未税） | 行「税率」列 → 该物料 `tax_rate` → 13 |

物料导入需特别注意：`Item.purchase_price` 流入 `apps/inventory/mrp.py:352` 作为 MRP 采购建议金额，`standard_cost` 是 `apps/inventory/cost_accounting.py:467` 的库存成本兜底单价。两者都是记账基准，必须存未税值。

（`apps/oa/asset.py` 的 `purchase_price` 是固定资产模块的同名字段，与物料无关，不在范围内。）

## 实现

### 公共解析器

新增 `apps/core/price_parsing.py`：

```python
def resolve_import_prices(row, columns, tax_rate) -> (未税, 含税, 实际税率)
```

三处 `import_excel` 现在各写各的价格解析，逻辑重复且已经漂移。提取公共实现，消除漂移来源。

### 列识别顺序

`find_column` 是子串匹配，「含税单价」本身含「单价」。识别顺序固定：

1. 「未税单价」/「未税价」/「不含税单价」
2. 「含税单价」/「含税价」
3. 裸「单价」——**必须排除已被前两者认领的列**

采购申请那处已有此处理（`apps/purchase/views.py:478-485`），本次提取为公共实现。

### 导入模板

三个 `export_template` 的表头要标注口径，裸「单价」列明确标为含税。避免用户拿旧模板填未税价却被按含税反算——那会算出偏低的入账价。

### 导入预览

用户上传后、落库前，预览显示反算结果：`含税单价 319.20 → 未税 282.48 @13%`。

这是本次改动最重要的防错措施：口径判断错了，用户在落库前有机会发现。

### 新建页默认口径

采购申请新建页的「单价口径」开关默认值从 `EXCLUSIVE` 改为 `INCLUSIVE`，与导入口径保持一致——两条录入路径不能一个按含税、一个按未税。

只改前端新建时的初始值（`RequestList.vue` 的 `form` 初值与 `resetForm`），**不改模型字段 `default`**：模型默认值是存量语义的锚，改了会让直接走 ORM 创建的历史路径（BOM 生成、旧导入）跟着变。用户仍可随时切回未税。

### 存量数据

**不动。** 已导入的 231 条申请明细、127 条订单明细存的是未税价，本次改的是解析规则，不改历史数据、不写迁移。

## 测试

TDD，先写测试再改实现。核心用例锚在 319.20 含税 ↔ 282.48 未税 @13%。

- 三个入口各自：只有裸「单价」列 → 按含税反算
- 有「未税单价」列 → 原样入账，不反算
- 两列都有 → 各按各的
- 「含税单价」列不被裸「单价」的子串匹配误认
- 行税率覆盖表头税率（6% 与 13% 混排一张表）
- 物料导入：`purchase_price` 反算后 MRP 取到未税值
- 边界：空单价、0、非数字、税率为 0
- 新建页默认口径为含税，且模型 `default` 未被改动（直接 ORM 创建仍是 EXCLUSIVE）

外加 `scripts/precheck.sh`、相关测试分组、集成测试、前端 `vue-tsc` 与 eslint。

## 不做什么

- 不翻转 `unit_price` / `estimated_price` 的语义
- 不改库存成本、进项抵扣、预算校验的计算基准
- 不迁移存量数据
- 不改 `PurchaseRequest.price_input_mode` 的模型默认值（只改前端新建时的初始值）
- 不改采购订单页的口径默认值（订单口径从来源申请继承，已在上一轮实现）
