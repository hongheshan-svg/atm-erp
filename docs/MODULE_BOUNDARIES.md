# Lean ERP 模块边界

2026-09-09 按用户要求，将销售独立为第九个入口。保留三个本地 Django app 与六种固定角色；模块独立不增加微服务、消息队列或配置化流程。

| 模块 | 维护的事实 | 与其他模块的联系 |
| --- | --- | --- |
| 销售 | 需求、报价、合同金额与签约日期 | 签约调用项目建档和财务应收入口；一个销售单最多关联一个项目 |
| 项目 | 执行人员、计划、任务、工时、交付和售后 | 引用客户；合同金额只读投影销售事实；可直接创建内部项目 |
| BOM | 项目物料需求与修订 | 按库存、已领料、采购在途计算缺料，不维护第二份库存 |
| 采购 | 采购单、供应商、单价及收退进度 | 按需引用 BOM；批准产生应付，收货形成库存移动 |
| 库存 | 库位余额与不可覆盖的移动记录 | 引用采购、项目或售后任务，实际领退料提供成本 |
| 收付款 | 应收应付、费用、收付款与冲销 | 接受业务来源，保留原始金额流水，服务端计算余额 |
| 基础资料 | 物料、客户、供应商 | 其他模块通过标识引用，不复制主数据 |
| 设置 | 用户、公司信息、编号规则、审计 | 固定角色授权、编号与审计为公共能力 |
| 工作台 | 无独立业务账 | 按角色读取各模块待办 |

前端 `src/views/*Page.vue` 提供明确路由，`src/modules/` 分别维护模块表单、列表列及动作。`business.ts` 只分发资源，不集中实现业务动作。公共字段控件、表格、弹窗、请求与目录加载继续复用；目录按模块所需加载，销售不依赖项目或库存接口才能创建报价。

后端 `business/api/` 按领域拆开接口，`business/services/` 承担状态校验和事务动作。销售的签约事务先锁销售单，再建立执行项目，并交给收付款服务生成应收。任一步骤失败则全部回滚，包括编号、审计与防重复凭据。签约后销售金额保持不变，执行中止和款项冲销各自处理且保留关联历史。

当前 Lean 数据库通过 `0003_sales_order` 向前迁移，将原项目商业字段移入销售单；项目编号、成员、业务外键和流水保留。原项目上的商业字段改为只读投影，不允许两处编辑。迁移不支持旧版全量 ERP，也不绕过 schema guard。
