# Lean ERP 模块边界

按用户要求独立销售模块，当前保留十个业务入口、三个本地 Django app 与七种固定角色。销售经理负责本人销售订单，签约时指定项目经理执行；模块独立不增加微服务、消息队列或配置化流程。

| 模块 | 维护的事实 | 与其他模块的联系 |
| --- | --- | --- |
| 销售 | 需求、报价、合同编号、合同金额与签约日期 | 签约调用项目建档和财务应收入口；一个销售单最多关联一个项目，合同编号只在销售维护 |
| 项目 | 执行人员、计划、任务、工时、交付、售后及三类预算 | 引用客户；合同金额只读投影销售事实；实际和承诺成本从原业务计算，预算更正保留版本和审计 |
| BOM | 项目物料需求与修订 | 按库存、已领料、采购在途计算缺料，不维护第二份库存 |
| 采购 | 采购单、供应商、单价及收退进度 | 按需引用 BOM；批准核对项目预算并产生应付，超额明确确认、保留核算快照；收货形成库存移动 |
| 库存 | 库位余额与不可覆盖的移动记录 | 引用采购、项目或售后任务，实际领退料提供成本 |
| 收付款 | 应收应付、费用、收付款与冲销、对账确认及银行匹配证据 | 接受业务来源，保留原始金额流水；对账保存源单快照和核准额度，银行认领复用 Payment，匹配与未认领款退回不重复记账 |
| 基础资料 | 物料、客户、供应商 | 其他模块通过标识引用，不复制主数据；新建物料可手填编码，仍复用公共编号锁防重，保存后编码不变 |
| 设置 | 用户、公司信息、编号规则、审计 | 固定角色授权、编号与审计为公共能力；管理员改规则仅影响新记录，不提供历史业务编号改写 |
| 工作台 | 无独立业务账 | 按角色读取各模块待办 |
| 经营报表 | 无独立业务账 | 固定只读聚合，复用 finance.costs 与预算承诺投影；管理员或单独授权的总经理可看 |

前端 `src/views/*Page.vue` 提供明确路由，`src/modules/` 分别维护模块表单、列表列及动作。`business.ts` 只分发资源，不集中实现业务动作。公共字段控件、表格、弹窗、请求与目录加载继续复用；目录按模块所需加载，销售不依赖项目或库存接口才能创建报价。

后端 `business/api/` 按领域拆开接口，`business/services/` 承担状态校验和事务动作。销售的签约事务先锁销售单，再建立执行项目，并交给收付款服务生成应收。任一步骤失败则全部回滚，包括编号、审计与防重复凭据。签约后原签约金额保持不变，只有正式补充协议可更新现行合同金额；协议先锁项目再锁销售及款项，保留不可变协议快照。执行中止和款项冲销各自处理且保留关联历史。

评审整改沿用这些边界：BOM维护单元用量、库存仍按物料共享；采购维护隔离待处理到货，合格后才调用原库存写入；付款引用同项目凭据，附件仍统一鉴权；项目估算是独立计划输入，不成为实际成本。预算调整人与超额批准人分离（管理员需说明例外原因），不新增角色表或审批引擎。

当前 Lean 数据库通过 `0003_sales_order` 向前迁移，将原项目商业字段移入销售单；项目编号、成员、业务外键和流水保留。原项目上的商业字段改为只读投影，不允许两处编辑。迁移不支持旧版全量 ERP，也不绕过 schema guard。
